# 多 Pod 双故障完整演示

业务网包含 11 台设备、12 条链路：POD-01/02/03 各一台 Spine、两台 Leaf，上联 Core-01/02。独立验证 Fabric B 另有两台设备。

checkout 服务从 POD-02 双接入访问 POD-03：

- Leaf-03 / Ethernet1/49 主路径 down，长日志含 loss_of_signal。
- Leaf-04 / Ethernet1/50 备用路径 up，但 30 秒新增 100000 个接收包、5000 个 CRC 错误包，增量错误率 5%。
- 目的 Leaf-05 接口正常，用于对照及跨 Pod 定位。

## 一条命令启动

在项目根目录、conda agent310 环境执行：

```text
python demo/run_walkthrough.py
```

打开 http://127.0.0.1:18090 ，新建对话，点击“多 Pod · 主备链路双故障”。端口 18000/18080/18090 与正式服务分开。Ctrl+C 会停止三个演示子进程；不覆盖正式配置。配置位于 `demo/walkthrough.toml`：`server.port`、`frontend.port` 和 `mcp.servers.demo.url` 分别指定三个端口；`frontend.backend_url` 留空自动跟随后端。启动器和占用检查均读取这些配置。会话按 session_id 保存到 `data/demo/sessions/`，数据库也独立保存，避免与正式服务同时运行时互相影响。

此模式**固定决策步骤，不调用大模型**。界面明确显示“DEMO 固定决策 · 实际工具执行”。不是播放伪造的成功事件：每一步真实经过 Agent、MCP HTTP、技能加载、本机 Python、结果存储、检索和 SSE。任一步骤失败会终止，case_id、脚本采样、日志 artifact_id 和读取位置都来自本次真实返回。用于稳定检查功能，不证明模型能自主完成排查。固定摘要仅用于演示上下文压缩链路。

切换为实际大模型自主执行：先停止演示，然后运行：

```text
python demo/run_walkthrough.py --model
```

两个模式均可使用首页按钮，或输入：

> 请运行多 Pod 双故障完整演示：加载 dcn-path-investigation 技能，读取参考流程并创建独立 DEMO 实例。排查 checkout 主备路径，执行计数器分析脚本，检索并读取长日志证据。授权仅对该 DEMO 实例执行模拟修复，然后复查接口、计数器和业务主备状态，给出报告。

固定入口只接受上面与按钮一致的完整样例，其他输入只显示使用说明，不执行工具，以免把只读问题误当作模拟修复授权。真实模型入口没有此样例限制。

真实模型自行规划和选工具，不保证动作顺序与固定演示一致。若步骤不足，可调整 agent.max_steps。正式入口也可使用该场景。修改工具或技能后，重启 MCP 和后端加载配置。

## 应当看到的过程

1. skill.load 加载技能，skill.read 按需读取参考流程。
2. mcp.list_tools 发现工具，start_demo_case 创建独立实例，查询业务主备路径和基线状态。
3. 查询 Leaf-03 时自动显示 POD-02，主设备及链路标红；查询 Leaf-04 时另一个节点也标红。它虽为 up，但 health_status=degraded。
4. skill.run 实际执行 analyze_counters.py，展开返回可见错误率 5%。
5. 查询 Leaf-05 时定位切换 POD-03；查询 Leaf-03 日志时回到 POD-02。
6. 约 46 万字符单行日志先摘要展示，再通过 artifact.search/read 检索 loss_of_signal 并读取附近原文。
7. repair_demo_link 分别模拟更换光模块和线缆；动作卡片返回成功时不立即清除拓扑异常，复查接口健康后才清除。
8. 再次运行采样脚本得到 0%；最终业务主备路径均健康，1000 次请求全部成功。

共 21 次工具调用、22 个决策步骤、2 次本机脚本执行。工具参数、结果可展开；“范围”选择器可切换全网、指定 Pod 或自动跟随排查。上下文压缩事件按预算自然出现。异常字段随工具事件保留，因此大结果被摘要后仍可定位。

## 数据与边界

- 所有接口、日志、业务请求及更换动作都是 DEMO 模拟，无真实设备操作。
- 每次演示创建独立 case_id。模拟修复只影响此实例，其他实例和未指定 case_id 的只读故障基线不受影响。
- 主链路恢复后业务可以不丢包，但备用链路仍异常时不会报告整体 healthy。
- 模拟修复幂等，重复调用返回 already_applied。停止流程不会撤销已经完成的模拟动作；重新演示创建新实例即可。
- MCP 进程内保存实例，重启后实例失效；会话日志和完整结果仍在原会话目录。演示不是持久化设备数据库。
- 本机脚本仅计算输入数字。计数回退、时间倒序、无流量等不能当作健康，脚本分别报错或返回 unknown。
- 历史日志保留旧故障；不能以旧日志取代修复后的状态和计数器验证。

技能、参考流程、脚本位于 `skills/dcn-path-investigation/`。修改采样数据在 `demo/demo_mcp_server.py`；修改固定演示步骤在 `demo/run_walkthrough.py` 的 steps 列表。
